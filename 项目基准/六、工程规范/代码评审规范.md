# 代码评审规范

> 状态：已确认

## 目的
规范代码评审的流程和标准，确保代码质量。

## 适用范围
所有 PR 和代码变更。

## 规范内容

### 评审流程
1. 提交者创建 PR
2. 自动检查通过（CI、测试）
3. 至少 1 人 review
4. 所有评论已解决
5. 合并到目标分支

### 评审标准

#### 功能正确性
- [ ] 功能符合需求
- [ ] 边界情况已处理
- [ ] 错误情况已处理

#### 代码质量
- [ ] 代码清晰易读
- [ ] 命名合理
- [ ] 无重复代码
- [ ] 函数职责单一

#### 安全性
- [ ] 输入已验证
- [ ] 权限已校验
- [ ] 无敏感信息泄露
- [ ] 无 SQL 注入风险

#### 性能
- [ ] 无不必要查询
- [ ] 无 N+1 查询
- [ ] 无内存泄漏风险

#### 测试
- [ ] 新功能有对应测试
- [ ] 测试覆盖边界情况
- [ ] 测试已通过

### 评审评论规则
- 使用 `@username` 标记需要回应的人
- 评论使用 `[BLOCK]`、`[SUGGEST]`、`[NIT]` 标记严重程度
- `[BLOCK]`：必须修改，否则不能合并
- `[SUGGEST]`：建议修改，可选
- `[NIT]`：细节问题，可选
- 评论解决后标记为 `Resolved`

## 禁止事项
- 禁止跳过评审直接合并
- 禁止在评审中讨论功能（应提前讨论）
- 禁止在评审中攻击个人
- 禁止提交无测试的大变更
- 禁止 CI 不通过就合并
