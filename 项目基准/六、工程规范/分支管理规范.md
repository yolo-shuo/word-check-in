# 分支管理规范

> 状态：已确认

## 目的
规范 Git 分支的使用策略，确保开发流程有序。

## 适用范围
所有 Git 分支操作。

## 规范内容

### 分支策略

| 分支 | 说明 | 从何处创建 | 合并到 |
|---|---|---|---|
| `main` | 生产分支 | - | 生产发布 |
| `dev` | 开发分支 | `main` | `main` |
| `feature/*` | 功能分支 | `dev` | `dev` |
| `fix/*` | 修复分支 | `dev` | `dev` |
| `hotfix/*` | 紧急修复 | `main` | `main` + `dev` |

### 分支命名
- 功能：`feature/打卡创建`
- 修复：`fix/连续天数bug`
- 热修复：`hotfix/登录崩溃`

### 工作流程
1. 从 `dev` 创建功能分支
2. 在功能分支开发
3. 提交 PR 到 `dev`
4. 通过 review 后合并到 `dev`
5. 功能完成后，将 `dev` 合并到 `main`

### PR 规范
- 标题：Conventional Commits 格式
- 描述：说明变更内容、测试结果
- 必须通过所有测试
- 至少 1 人 review

## 禁止事项
- 禁止直接推送到 `main`
- 禁止直接推送到 `dev`（必须通过 PR）
- 禁止分支名使用英文（项目为中文）
- 禁止长期存在不合并的分支
- 禁止在 `main` 上进行开发
