# Git 提交规范

> 状态：已确认

## 目的
规范 Git 提交消息的格式，确保提交历史清晰可读。

## 适用范围
所有 Git 提交。

## 规范内容

### 提交消息格式
```
<type>: <description>

[optional body]

[optional footer]
```

### 提交类型

| 类型 | 说明 | 示例 |
|---|---|---|
| `feat` | 新功能 | `feat: 添加打卡创建功能` |
| `fix` | 修复 Bug | `fix: 修复连续天数计算 bug` |
| `docs` | 文档变更 | `docs: 更新 API 文档` |
| `style` | 样式调整 | `style: 调整组件样式` |
| `refactor` | 重构 | `refactor: 重构统计服务` |
| `test` | 测试相关 | `test: 添加连续天数测试` |
| `chore` | 构建/工具 | `chore: 更新依赖` |
| `perf` | 性能优化 | `perf: 优化查询性能` |

### 提交规则
1. 一行提交描述不超过 72 个字符
2. 描述使用动词开头
3. 不使用句号结尾
4. 描述具体做了什么，而非做了什么
5. 一次提交只做一件事

### 示例
```
feat: 添加打卡创建功能

- 添加 checkinRouter.create 路由
- 添加打卡表单组件
- 添加重复打卡检查

Closes #123
```

## 禁止事项
- 禁止提交消息为空
- 禁止提交消息使用英文（项目为中文）
- 禁止一次提交包含多个不相关变更
- 禁止提交调试代码（console.log 等）
- 禁止提交 `.env.local` 文件
