# 认证与权限规范

> 状态：已确认

## 目的
规范用户认证和权限校验逻辑，确保数据安全。

## 适用范围
所有需要登录或权限校验的功能。

## 规范内容

### 认证方式
- 使用 NextAuth v4 (credentials provider)
- 密码哈希：argon2
- 会话管理：JWT session

### 权限模型

| 角色 | 权限 |
|---|---|
| 游客 | 浏览公开页面 |
| 用户 | 登录、创建/加入圈子、打卡、互动 |
| 圈子成员 | 查看圈子数据、打卡、点赞、评论 |
| 圈子所有者 | 管理圈子设置、移除成员、转移所有权 |
| 管理员 | 审计日志、移除内容、修正记录 |

### 权限校验函数
```tsx
// 校验圈子成员
async function assertCircleMember(userId: string, circleId: string) {
  const member = await prisma.circleMember.findFirst({
    where: { userId, circleId, leftAt: null },
  })
  if (!member) {
    throw new TRPCError({ code: 'FORBIDDEN', message: '没有权限' })
  }
  return member
}

// 校验圈子所有者
async function assertCircleOwner(userId: string, circleId: string) {
  const circle = await prisma.circle.findFirst({
    where: { id: circleId, ownerId: userId },
  })
  if (!circle) {
    throw new TRPCError({ code: 'FORBIDDEN', message: '没有权限' })
  }
}
```

### 权限校验顺序
1. 先校验是否登录
2. 再校验是否是圈子成员
3. 最后校验具体角色权限
4. 避免先查数据再校验权限（可能暴露数据存在）

### 审计日志
以下操作必须写入 `audit_logs`：
- 创建打卡 (`CHECKIN_CREATE`)
- 编辑打卡 (`CHECKIN_EDIT`)
- 撤回打卡 (`CHECKIN_WITHDRAW`)
- 重置密码 (`PASSWORD_RESET`)
- 移除成员 (`MEMBER_REMOVE`)
- 转移所有者 (`OWNER_TRANSFER`)
- 管理员移除内容 (`ADMIN_REMOVE`)
- 管理员修正记录 (`ADMIN_CORRECTION`)

## 禁止事项
- 禁止在前端做权限校验（必须后端校验）
- 禁止跳过权限校验直接查询数据
- 禁止返回用户不存在/资源不存在的区别
- 禁止在日志中记录密码明文
- 禁止跳过审计日志
