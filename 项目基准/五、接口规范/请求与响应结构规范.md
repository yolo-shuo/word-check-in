# 请求与响应结构规范

> 状态：已确认

## 目的
规范 API 请求和响应的数据结构，确保前后端交互一致。

## 适用范围
所有 tRPC 路由的 input 和 output。

## 规范内容

### 分页结构
```tsx
// 请求
{ skip: 0, take: 20 }

// 响应
{
  data: [...],
  total: 100,
  page: 0,
  pageSize: 20,
  totalPages: 5,
}
```

### 错误响应
```tsx
// tRPC 错误结构
{
  error: {
    code: 'CONFLICT' | 'FORBIDDEN' | 'UNAUTHORIZED' | 'NOT_FOUND' | 'BAD_REQUEST' | 'INTERNAL_SERVER_ERROR',
    message: '错误描述',
  }
}
```

### 数据过滤
- 返回给前端的数据必须过滤敏感字段
- `email`、`passwordHash` 不返回
- `deletedAt` 不为 null 的数据不返回
- 使用 `select` 明确指定返回字段

### 关联查询
- 使用 `include` 或 `select` 指定关联数据
- 关联查询必须明确指定需要字段
- 避免不必要的 N+1 查询

### 时间格式
- 日期类型：`yyyy-MM-dd`
- 日期时间类型：ISO 8601
- 前端显示：使用 `date-fns` 格式化

## 示例
```tsx
// 正确：明确 select 字段
return ctx.prisma.checkin.findMany({
  where: { circleId, status: 'PUBLISHED', deletedAt: null },
  select: {
    id: true,
    wordCount: true,
    minutes: true,
    note: true,
    date: true,
    createdAt: true,
    user: { select: { nickname: true, avatarUrl: true } },
  },
  orderBy: { date: 'desc' },
})

// 错误：返回完整模型
return ctx.prisma.checkin.findMany({ where: { circleId } })
```

## 禁止事项
- 禁止返回未过滤的完整模型
- 禁止不指定 select/include 直接查询
- 禁止在前端做数据格式转换（应在后端）
- 禁止返回时间戳而非格式化日期
