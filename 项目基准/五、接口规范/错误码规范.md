# 错误码规范

> 状态：已确认

## 目的
统一 API 错误码和错误消息，确保错误处理一致。

## 适用范围
所有 tRPC 路由和前端错误处理。

## 规范内容

### 错误码定义

| 错误码 | HTTP 状态 | 场景 | 示例 |
|---|---|---|---|
| `BAD_REQUEST` | 400 | 输入验证失败 | zod 校验不通过 |
| `UNAUTHORIZED` | 401 | 未登录或会话过期 | 未提供有效 token |
| `FORBIDDEN` | 403 | 无权限操作 | 非圈子成员访问圈子资源 |
| `NOT_FOUND` | 404 | 资源不存在 | 打卡不存在 |
| `CONFLICT` | 409 | 资源冲突 | 今天已打卡 |
| `INTERNAL_SERVER_ERROR` | 500 | 服务器内部错误 | 未预期的异常 |

### 错误处理模式
```tsx
import { TRPCError } from '@trpc/server'

// 业务错误
throw new TRPCError({
  code: 'CONFLICT',
  message: '今天已经打过卡了',
})

// 权限错误
throw new TRPCError({
  code: 'FORBIDDEN',
  message: '没有权限执行此操作',
})

// 验证错误
throw new TRPCError({
  code: 'BAD_REQUEST',
  message: '输入参数不合法',
})
```

### 前端错误处理
```tsx
try {
  await mutation.mutateAsync(input)
  toast({ title: '操作成功' })
} catch (error) {
  if (error instanceof TRPCClientError) {
    switch (error.data?.code) {
      case 'CONFLICT':
        toast({ title: '操作冲突', variant: 'destructive' })
        break
      case 'FORBIDDEN':
        toast({ title: '权限不足', variant: 'destructive' })
        break
      default:
        toast({ title: '操作失败', variant: 'destructive' })
    }
  }
}
```

## 禁止事项
- 禁止暴露内部错误详情（如 SQL 错误）
- 禁止使用 `INTERNAL_SERVER_ERROR` 处理业务错误
- 禁止错误消息包含敏感信息
- 禁止前端忽略错误处理
