# 需求与问题记录格式

> 状态：已确认

## 目的
统一需求、缺陷、任务的记录格式，便于追踪和管理。

## 适用范围
所有新功能需求、发现的 Bug、待办任务。

## 规范内容

### 文件结构

```markdown
## 编号：REQ-001 / BUG-001 / TASK-001

- 类型：需求 / 缺陷 / 任务
- 状态：待确认 / 进行中 / 已完成 / 已驳回
- 提出人：
- 提出日期：
- 优先级：P0 / P1 / P2 / P3

### 描述
一句话说清问题或需求。

### 现状
当前是什么样，或当前为什么做不到。

### 期望
应该变成什么样。

### 验收标准
- 可逐项勾选的验收条件

### 关联规范
涉及修改的项目基准文件。

### 变更记录
| 日期 | 变更内容 | 修改人 |
```

### 编号规则
- REQ-XXX：需求
- BUG-XXX：缺陷
- TASK-XXX：任务
- 编号递增，不重复，不复用

### 状态流转
```
待确认 → 进行中 → 已完成
     → 已驳回
```

### 优先级定义
| 优先级 | 含义 | 响应时间 |
|---|---|---|
| P0 | 阻塞性问题 | 立即处理 |
| P1 | 重要问题 | 1 天内 |
| P2 | 一般问题 | 本周内 |
| P3 | 低优先级 | 有空时处理 |

## 示例

```markdown
## 编号：BUG-001

- 类型：缺陷
- 状态：进行中
- 提出人：张三
- 提出日期：2026-09-30
- 优先级：P1

### 描述
打卡后动态流未显示最新的打卡记录。

### 现状
打卡成功后动态流仍显示旧数据，需要手动刷新。

### 期望
打卡成功后动态流自动更新，展示最新的打卡记录。

### 验收标准
- [ ] 打卡成功后动态流自动刷新
- [ ] 新打卡记录出现在列表顶部
- [ ] 其他成员也能看到新打卡

### 关联规范
- 五、接口规范 / API设计规范.md

### 变更记录
| 日期 | 变更内容 | 修改人 |
|---|---|---|
| 2026-09-30 | 记录问题 | 张三 |
```
